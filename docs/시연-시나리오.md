## 0. 이 문서의 사용법

이 문서는 세 부분이다.

| 부 | 내용 | 언제 쓰는가 |
|---|---|---|
| **1부** | 촬영 전 준비 (계정·데이터·환경 세팅) | 촬영 D-1 |
| **2부** | 씬별 촬영 대본 (컷 리스트 + 나레이션) | 촬영 당일 |
| **3부** | 테스트 시나리오 (기능 검증 표) | 촬영 D-2 ~ D-1, 그리고 상시 QA |

**핵심 원칙 세 가지**

1. **촬영 전에 3부의 테스트를 전부 돌린다.** 카메라 앞에서 처음 눌러 보는 버튼이 하나라도 있으면 안 된다.
2. **데이터를 미리 심어 둔다.** "승인 대기 매물이 0건이라 관리자 화면이 비어 있음" 같은 사고가 가장 흔하다.
3. **역할 전환은 편집으로 감춘다.** 로그아웃-로그인 장면은 시연 가치가 없으므로 컷한다. 단, 역할별 화면이 다르다는 것 자체는 한 번 보여 준다.

# 1부. 촬영 전 준비

## 1-1. 촬영 환경 결정

| 항목 | 권장 | 이유 |
|---|---|---|
| 대상 환경 | **배포 환경 (`https://rentversal.site`)** | ALB·Route53·HTTPS·Docker까지 실제로 돌아간다는 증거가 된다. 로컬은 "만들다 만 것"처럼 보인다 |
| 백업 환경 | 로컬 (Vite + Spring 9022 + FastAPI) | 배포 장애 대비. 배포/로컬 어느 쪽으로 찍어도 화면은 같아야 한다 |
| 브라우저 | Chrome, 시크릿 창 X (로그인 상태 유지 필요) | 확장 프로그램·북마크바 전부 끄기 |
| 해상도 | 1920×1080 고정, 브라우저 100% 확대 | 지도·비교표가 잘리지 않는 최소 폭 |
| 녹화 | OBS, 30fps로 충분 / 마우스 하이라이트 켜기 | 클릭 위치가 보여야 한다 |
| 나레이션 | 후시 녹음 권장 | 조작 중 말하면 로딩 대기 구간에서 말이 끊긴다 |

**촬영 전 브라우저 정리**
- 주소창에 개인 검색 이력이 뜨지 않게 자동완성 정리
- 개발자 도구 닫기 (단, 챗봇/API 연동을 강조할 컷에서는 Network 탭을 의도적으로 열어 보여 줘도 좋다)
- 알림 권한 팝업, 소셜 로그인 팝업 차단 해제 미리 확인

## 1-2. 계정 준비표

역할별로 **미리 만들어 두고, 상태를 확정해 둔다.**

| # | 역할 | 용도 | 필요한 상태 |
|---|---|---|---|
| A1 | GUEST (비로그인) | 1막 도입, 로그인 유도 가드 | 로그아웃 상태 |
| A2 | USER (신규) | **취향 초기 설정 시연 전용** | 가입만 하고 `preferenceCompleted = false` 로 유지 |
| A3 | USER (숙성) | 추천·관심·비교·상담·마이페이지 | 관심 매물 4건 이상, 최근 본 매물 있음, 평가 이력 있음, 보낸 상담 1건은 **답변 완료**, 1건은 **답변 대기** |
| A4 | USER (소셜) | 카카오/구글/네이버 로그인 시연 | 최초 로그인 시 추가정보 입력 화면(`/oauth/signup`)이 뜨도록 **미가입 상태 1개는 남겨 둘 것** |
| A5 | BROKER (인증 완료) | 매물 등록·관리·문의 답변 | 중개사무소 등록 완료 + 인증 마크 보유, 등록 매물 5건 이상(게시중/대기/완료 섞기), 미답변 상담 2건 |
| A6 | BROKER (미인증) | 인증 신청 시연 전용 | `UNVERIFIED` 상태 유지. 사무소 미등록 상태의 안내 화면도 여기서 찍는다 |
| A7 | BROKER (패스워드리스 미등록) | 패스워드리스 QR 등록 시연 | 일반 가입 직후 `/member/passwordless` 로 넘어가는 상태 |
| A8 | ADMIN | 콘솔 전체 | 처리할 일이 **비어 있지 않아야 함** (아래 데이터 준비 참고) |

> **주의** — A2는 소모품이다. 취향 설정을 한 번 마치면 다시 못 본다. **여분 계정 2개**를 더 만들어 두고, NG가 나면 다음 계정으로 다시 찍는다. (DB에서 되돌릴 수 있으면 그것도 방법이다: `UPDATE member SET preference_completed = 0 WHERE email = '...'` — 실제 컬럼명은 확인할 것)

## 1-3. 데이터 준비 체크리스트

관리자 콘솔과 중개인 대시보드는 **비어 있으면 시연이 성립하지 않는다.** 촬영 전날 아래를 채운다.

**매물**
- [ ] 승인 대기(PENDING) 매물 **3건 이상** — 관리자 승인/반려/수정요청을 각각 다른 건으로 시연
- [ ] 저평가(UNDERVALUED) 판정 매물이 지도에 **눈에 띄게 여러 개** — 지도 강조색이 안 보이면 하이라이트 컷이 죽는다
- [ ] 3일 이내 등록 매물 몇 건 (매물 확인 페이지 `new` 배지용)
- [ ] **같은 거래유형** 매물 2건 이상을 A3 계정 관심 목록에 등록 (비교 페이지 필수 조건)
- [ ] 거래유형이 **다른** 매물 조합도 관심 목록에 하나 넣어 둔다 (비교 제한 안내 컷용)
- [ ] 사진이 3장 이상 붙은 매물 1건 (라이트박스/캐러셀용)
- [ ] 좌표가 정상인 매물만 지도 컷에 등장하도록, 촬영 지역(예: 강남구·마포구)의 매물 좌표 점검

**동네**
- [ ] 한줄평이 충분히 쌓인 행정동 1~2곳 (워드클라우드가 초라하면 안 된다)
- [ ] 군집 3종(녹지·교통 / 생활편의·의료 / 조용한 주거)이 **각각 최소 1곳씩** 예시로 지목 가능해야 함
- [ ] 동네 상세에 대표사진이 들어간 곳 1곳

**운영**
- [ ] 심사 대기 중개인 인증 신청 **2건** (승인용 1, 반려용 1)
- [ ] 미처리 신고 **2건** (허위 매물 1, 부적절 한줄평 1)
- [ ] 미답변 상담 **2건** (중개인 문의 관리용)
- [ ] 공지사항 3건 이상 (목록·페이지네이션이 보이도록)
- [ ] 모델 관리 화면에 학습 메타데이터·군집 결과·텍스트마이닝 결과가 **모두 채워져 있는지** (`prentversal/outputs` 산출물이 ML EC2에 올라가 있어야 함)

## 1-4. 촬영 직전 스모크 테스트 (60분 전, 15분 소요)

| 순서 | 확인 | 실패 시 |
|---|---|---|
| 1 | `https://rentversal.site` 200 응답, HTTPS 자물쇠 | ALB / ACM 확인 |
| 2 | 로그인 → JWT 발급 → 헤더에 프로필 표시 | Spring 컨테이너 로그 |
| 3 | 지도 검색에서 **마커가 실제로 찍히는지** | Kakao Maps 키 도메인 등록 확인 |
| 4 | 매물 상세 AI 시세 그래프 렌더 | FastAPI(ML EC2) 헬스체크 |
| 5 | 맞춤 추천 카드 3장 정상 | FastAPI 다운 시 Spring 폴백으로 대체되므로 **점수 근거 문구가 나오는지**로 판단 |
| 6 | 챗봇에 "안녕" 한 마디 | OpenAI 키·잔액 |
| 7 | 패스워드리스 QR 발급 | `auth.rentversal.site:8143` 접속 확인 |
| 8 | 이미지 업로드 1건 | S3 자격증명 |
| 9 | 상담 접수 → 중개인 이메일 도착 | Spring Mail 설정 |
| 10 | 관리자 콘솔 각 탭 데이터 존재 | 1-3 데이터 준비 재확인 |

> 이 10개 중 하나라도 실패하면 **그 기능은 대본에서 빼고 찍는다.** 촬영 중에 고치려 들면 시간이 몇 배로 든다.

# 2부. 씬별 촬영 대본

## 2-0. 전체 구성과 러닝타임

아래 씬별 시간을 모두 더하면 **약 22분**이다. ★ 표시된 씬만 남기면 **약 14분**.
발표에 넣을 8분 버전이 필요하면 ★만으로도 부족하므로, 5부의 "반드시 남아야 하는 6개 컷"까지 줄인다.

| 막 | 관점 | 씬 | 시간 |
|---|---|---|---|
| 인트로 | — | S0 | 0:30 |
| **1막** | 일반 사용자 — "집을 구한다" | S1 ~ S18 | 12:25 |
| **2막** | 중개인 — "매물을 올린다" | S19 ~ S25 | 5:20 |
| **3막** | 관리자 — "서비스를 운영한다" | S26 ~ S32 | 3:20 |
| 아웃트로 | — | S33 | 0:30 |
| | | **합계** | **22:05** |

**촬영 순서 ≠ 편집 순서.** 아래 순서로 찍고 편집에서 재배열한다.

1. **관리자 계정으로 먼저 찍는다** (S26~S32) — 이때 승인 대기 매물을 일부 남겨 둔다
2. **중개인 계정** (S19~S25)
3. **비로그인 → 신규 사용자 → 숙성 사용자** (S1~S18) — 마지막에 찍어야 앞 단계에서 만든 데이터가 화면에 반영돼 있다

단, **매물 등록 → 관리자 승인 → 사용자에게 노출**의 연결을 한 흐름으로 보여 주고 싶다면 예외적으로 순서대로 찍는다. 이 경우 계정 전환 3회가 발생하므로, 전환 장면은 "역할 카드" 자막으로 덮는다.

## 1막 — 일반 사용자

### S1. 메인 페이지 (비로그인) — 0:40 ★
- **경로**: `/`
- **조작 순서**
  1. 최상단 히어로 + 검색창 노출 (2초 정지)
  2. 우측 **섹션 내비게이션**의 항목을 클릭 → 해당 섹션까지 스크롤 이동 (스크롤스파이가 따라 움직이는 것이 포인트)
  3. 섹션을 순서대로 훑는다: `공지사항` → `어디서 찾을까` → `맞춤 추천` → `이번 주 매물` → `매물 비교` → `동네 둘러보기` → `동네 이야기` → `이용 방법`
  4. 하단 푸터(둘러보기 / 이용안내 / 데이터 출처) 노출
- **보여줄 포인트**
  - 비로그인이면 CTA가 `회원가입` / `먼저 둘러보기`로 나온다 → **역할별 CTA 분기**
  - 맞춤 추천 섹션은 비로그인일 때 잠금 미리보기(`RecommendLockedPreview`)로 뜬다
  - 동네 이야기 섹션의 워드클라우드 이미지
- **나레이션**: "메인 화면은 로그인 여부와 역할에 따라 다르게 구성됩니다. 지금은 비회원이라 가입을 안내하고, 맞춤 추천 자리는 잠금 미리보기로 보입니다."

### S2. 비로그인 가드 — 0:20
- **조작**: 매물 하나를 열고 → **하트(관심)** 클릭 → 로그인 유도 → **한줄평 작성** 클릭 → 로그인 유도
- **나레이션**: "인증이 필요한 동작은 화면에서 먼저 안내하고, 서버에서도 같은 조건으로 다시 확인합니다."

### S3. 회원가입 (일반 사용자) — 0:40 ★
- **경로**: `/member/signup`
- **조작 순서**
  1. **역할 선택 카드**: `일반 사용자` / `중개인` 두 장이 있음을 보여 주고 → `일반 사용자` 선택
  2. 이름 / 전화번호 / 이메일 / 비밀번호 입력
  3. **일부러 틀린 값을 넣어 검증을 보여 준다**: 비밀번호 `1234` → "대문자+소문자+숫자+특수기호" 안내 노출
  4. 비밀번호 확인 불일치 → 오류 노출
  5. 이메일 중복 → 오류 노출 (미리 존재하는 이메일 하나 준비)
  6. **약관 동의** — 전체 동의 / 개별 동의, `이용약관` 링크를 눌러 `/terms` 전문이 열리는 것까지
  7. 정상 값으로 가입 완료
- **포인트**: 형식 검증은 프론트에서 즉시, 중복 검사는 서버에서 온다.

### S4. 로그인 — 0:25 ★
- **경로**: `/member/login`
- **조작**
  1. **최근 로그인 이메일 자동 채움** + **최근 사용한 로그인 방식 표시** 를 먼저 보여 준다 (반응이 좋은 디테일이다)
  2. 이메일/비밀번호 로그인
  3. (별도 컷) 소셜 로그인 버튼 3종 노출 → 카카오 클릭 → 동의 화면 → 최초 로그인이면 `/oauth/signup` 추가정보 입력 → 완료
- **포인트**: Spring Security + JWT(Access/Refresh), OAuth2 Client 3종.
- **촬영 주의**: 소셜 로그인 팝업에 **본인 실명·프로필 사진이 노출**된다. 필요하면 모자이크하거나 더미 계정으로 찍는다.

### S5. 취향 초기 설정 — 0:50 ★★ (핵심)
- **경로**: `/preference-setup` (로그인 직후 자동 진입)
- **조작 순서**
  1. **강제 가드 시연**: 주소창에 `/map` 을 직접 입력 → 다시 `/preference-setup` 으로 되돌아오는 것. 상단바·푸터·챗봇이 **모두 사라져 있는 것**도 함께 짚는다
  2. **1단계 키워드 선택** — 키워드 여러 개 선택 (최소 개수 미달이면 다음이 막히는 것도 보여 줌)
